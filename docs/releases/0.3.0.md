# 0.3.0 — server, CLI and the complete M3 surface

Everything in M3 except the first registry publish. Twenty-seven packages at
`0.3.0`; the per-package details are in each `CHANGELOG.md`.

## What a deck can do now

- **Declare a deck as data.** `swipeline init` writes a strict
  `swipeline.deck.json`; `parseDeckManifest` rejects unknown keys, so a typo fails
  at startup instead of being ignored.
- **Map an API in one command.** `swipeline source add <url>` samples the endpoint,
  infers a flat field map, writes the `source` block and previews the cards it
  would produce.
- **Preview a deck.** `swipeline dev` serves a playground on the real API routes
  with swipes stored in SQLite.
- **Run the server.** `swipeline serve --db` adds SQLite storage, and the server
  ranks server-side (`GET /deck/:id/next`), serves `later` (`GET /collections/:id`)
  and documents itself (`GET /openapi.json`).
- **Sync and export.** `@swipeline/store-remote` with an outbox, `swipeline export`
  / `import` for portable JSONL history, and HMAC-signed webhooks from
  `@swipeline/sinks`.
- **Start from a template.** `npm create swipeline@latest` scaffolds `blank`,
  `books`, `papers`, `recipes` or `products`; `quickstart.yml` scaffolds and builds
  all five weekly.
- **Share one look and one vocabulary.** `@swipeline/theme` owns the token
  palette, `@swipeline/i18n` owns the binding strings, and `@swipeline/cards` owns
  the `text` / `media` / `facts` templates that both bindings render.

## Breaking changes

Versions were placeholder `0.0.0` before this release; there are no published
versions to migrate from. Two naming changes landed along the way:

- The element's `set offline` became the `setOffline` store command.
- Token names are now `--swl-color-*`, `--swl-space-*` and `--swl-motion-*`. The
  older `--swl-accent`, `--swl-radius`, `--swl-gap` and `--swl-duration` still work
  as fallbacks, so existing overrides keep applying.

## Known gaps

- **Nothing is on npm yet.** Trusted publishing is blocked on the npm organisation
  and the repository transfer; the Release workflow is wired and waits on the
  `npm-publish` environment.
- **Templates resolve to the workspace.** `create-swipeline` writes `^0.3.0` for
  `@swipeline/*`; the weekly job links the workspace instead, because the packages
  cannot install from the registry until the first publish.
- **`compare` template, `react-native` / `vue` / `svelte` bindings, adapter
  registry and the accessibility audit** are scheduled in M4.
- **Manifests cannot express rank stages.** A custom pipeline needs
  `deck.config.ts`.

```bash
pnpm install && pnpm lint && pnpm typecheck && pnpm test && pnpm build
pnpm quickstart:verify            # scaffold every template
node scripts/check-templates.mjs --install   # and build them
swipeline bench --gate
```
