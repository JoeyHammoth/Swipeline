# 0.4.0 — Vue, Svelte and React Native bindings

Three more bindings on the same engine, and one version for the whole workspace.
Thirty packages at `0.4.0`; the per-package details are in each `CHANGELOG.md`.

## What a deck can do now

- **Vue 3.** `@swipeline/vue` exposes `<SwipeDeck>` as a slot-based component over
  the shared card templates and string catalog, and passes the binding
  conformance suite under jsdom and in Chromium.
- **Svelte 5.** `@swipeline/svelte` is a real `.svelte` component — a custom card
  is a snippet that receives the card — and passes the same suite in both
  environments. The package ships source, so the consumer's compiler owns it.
- **React Native / Expo.** `@swipeline/react-native` renders the shared templates,
  drags with `PanResponder` from React Native core (no Gesture Handler, no
  Reanimated, no dev client), and announces cards through `AccessibilityInfo`.
  `examples/books-expo` runs a scripted swipe on launch and bundles for iOS and
  Android in CI.
- **One version everywhere.** All thirty packages are in one Changesets `fixed`
  group, so a release moves them together and an app pins a single version
  instead of a matrix of ranges.
- **A wider accessibility net.** axe now runs the WCAG 2.1 and 2.2 rule sets as
  well as 2.0 against every binding fixture, and the
  [audit page](/reference/a11y-audit) records what passed and what still needs a
  person.

## Breaking changes

None in the APIs. Every package moves `0.3.0 → 0.4.0` because of the fixed group,
including packages that did not change; treat the shared version as a workspace
release stamp, not a promise that each package gained a feature.

`create-swipeline` now writes `^0.4.0` for `@swipeline/*` dependencies.

## Known gaps

- **Nothing is on npm yet.** Trusted publishing is blocked on the npm organisation
  and the repository transfer; the Release workflow waits on the `npm-publish`
  environment.
- **React Native is not device-verified.** The binding typechecks, its render
  tests pass against a mocked `react-native`, and the smoke app bundles for both
  platforms, but no device, simulator or emulator has launched it.
- **The accessibility audit's manual half is open.** No screen reader pass exists
  yet for any binding; the checklist on the audit page is the work remaining.
- **M4 is not finished.** The Expo demo still has to run on iOS and Android before
  the milestone's acceptance criteria are met.

## Verifying this release

```bash
pnpm install && pnpm lint && pnpm typecheck && pnpm test && pnpm build
pnpm examples:typecheck && pnpm examples:build
PLAYWRIGHT_CHANNEL=chrome pnpm e2e   # or `pnpm e2e` with Playwright's Chromium
pnpm check:boundaries && pnpm licenses:check && pnpm package:licenses
```
