# 0.4.1 — a palette that passes, and the deck running in CI

A patch release with no API changes. The default palette now clears AAA text
contrast and the 3:1 boundary minimum, two elements stopped failing on their own
dark surfaces, and the native smoke app runs on an Android emulator and an iOS
simulator. Thirty packages at `0.4.1`; per-package details are in each
`CHANGELOG.md`.

## What changed

- **The default palette is darker where it had to be.** Light `color-accent`
  `#2563eb → #1e40af` moves accent text from 5.17:1 to 8.72:1 on white, and the
  borders `#e5e7eb → #8a8f9b` and `#334155 → #64748b` move a hairline from
  1.24:1 and 1.73:1 to 3.24:1 and 3.77:1. A border below 3:1 is not a boundary a
  low-vision user can see, so the visible cost — a mid-grey outline and a deeper
  link blue — is the fix, not a regression. A theme that overrides these tokens
  keeps its own values and takes over the obligation.
- **Tag pills follow the palette.** The Web Component drew them on a fixed
  `#f3f4f6`, which put inherited light text on a near-white pill on a dark page.
  They use `color-bg`, `color-muted` and `color-border` now, as the React
  stylesheet already did.
- **Status and error text have a surface.** `<swipe-deck>` coloured them with
  `color-fg` but gave them no background, so on a dark page they were dark on
  dark. They now carry the palette's own background.
- **The React preview is `inert`.** `aria-hidden` alone did not take a custom
  card's links out of the tab order; the preview is no longer focusable.

## How the failures were found

An audit that only ran on the four binding fixtures could not see any of this.
Two new nets did:

- `pnpm e2e:examples` boots the four example decks and scans each with the same
  axe tag set. It runs nightly rather than per pull request, because the decks
  call live APIs.
- `examples/books-expo` runs on a real Android emulator (`android.yml`, weekly)
  and, from this release, on an iOS simulator (`ios.yml`, weekly): the app is
  built, installed, launched, and the job fails unless the scripted swipe reports
  its like. Both then read the platform's accessibility tree and fail unless at
  least three controls carry labels; the
  [audit page](/reference/a11y-audit) records what they print.

The [accessibility audit](/reference/a11y-audit) records the ratios, the two
findings and the remaining manual checklist.

`create-swipeline` scaffolds `^0.4.1` for the `@swipeline/*` packages.

## Breaking changes

None in the APIs. Every package moves `0.4.0 → 0.4.1` because of the fixed group,
including packages that did not change.

Two visual changes reach anyone on the default tokens: the accent is a deeper
blue and card and control borders are a visible grey. Both are deliberate.

## Known gaps

- **Nothing is on npm yet, and the pipeline cannot do it alone.** The Release
  workflow now reaches the registry and fails there, per package:
  `ERR_PNPM_FAILED_TO_PUBLISH: Failed to publish package @swipeline/core@0.4.1
  (status 404 Not Found)`. There is no npm credential: the repository holds no
  `NPM_TOKEN`, and OIDC provenance cannot bootstrap a package that does not
  exist, because npm only accepts a trusted publisher for a package already on
  the registry. The first publish needs a granular token with write access to the
  `@swipeline` scope, stored as `NPM_TOKEN`; the workflow passes it through. Until
  then these versions exist in the repository and not in a registry.
- **No person has looked at a deck.** The mobile runs prove the app launches and
  the engine answers; no screen reader has been attached, and layout is reviewed
  only by the automated checks. The
  [screen-reader script](/reference/a11y-manual-script) is the pass that would
  change that, written so a release can record a result instead of a promise.
- **M4 is not closed.** Its acceptance criterion is the Expo demo on iOS and
  Android: both are now exercised automatically, but the milestone also wants the
  audit's manual half, which is still open.

## Verifying this release

```bash
pnpm install && pnpm lint && pnpm typecheck && pnpm test && pnpm build
pnpm examples:typecheck && pnpm examples:build
PLAYWRIGHT_CHANNEL=chrome pnpm e2e   # or `pnpm e2e` with Playwright's Chromium
PLAYWRIGHT_CHANNEL=chrome pnpm e2e:examples
pnpm check:boundaries && pnpm licenses:check && pnpm package:licenses
```
