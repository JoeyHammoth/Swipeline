# Support

## Where to ask

| You need | Go to |
|---|---|
| Help using Swipeline, a "how do I…" question, design discussion | [GitHub Discussions](https://github.com/JoeyHammoth/Swipeline/discussions) |
| A reproducible bug | [Open a bug report](https://github.com/JoeyHammoth/Swipeline/issues/new?template=bug_report.yml) |
| A feature idea | [Open a feature request](https://github.com/JoeyHammoth/Swipeline/issues/new?template=feature_request.yml) |
| A new data source | [Adapter request](https://github.com/JoeyHammoth/Swipeline/issues/new?template=adapter_request.yml) |
| A documentation problem | [Docs issue](https://github.com/JoeyHammoth/Swipeline/issues/new?template=docs_issue.yml) |
| A security vulnerability | **Privately**, via [SECURITY.md](SECURITY.md) — never a public issue |
| A conduct concern | See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) |

## Before opening an issue

1. Search existing issues and discussions.
2. Check the [docs](https://joeyhammoth.github.io/Swipeline/), especially the
   quickstart and the page for the feature you are using.
3. Reduce the problem to the smallest reproduction: the deck config, the adapter
   mapping, the events, and the versions involved.

## What to expect

This is a volunteer, maintainer-led project. We aim to label and respond to new
issues and discussions within a few days, and to ship fixes for confirmed
high-impact bugs in the next patch release. There is no commercial support and
no SLA.

## Supported versions

Only the latest published version of each package is supported while the
project is pre-1.0. See [SECURITY.md](SECURITY.md) for the version table.
